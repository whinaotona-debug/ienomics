# イエノミクス（IENOMICS）

おうちのお手伝いを「お仕事」にして、報酬・貯金・投資・支払いまでを家族で体験できる **家庭内経済アプリ** です。

お小遣い帳アプリと違うのは、お金が「もらうもの」ではなく **働いて稼ぎ、運用し、支払うもの** として一周する点です。親は発注者、子どもは受注者として、実際の経済とほぼ同じ流れを毎日の暮らしのなかで体験できます。

---

## 何ができるか

### お仕事（受発注）

| 機能 | 説明 |
| --- | --- |
| 発注 | 親が仕事の内容・報酬・期限を決めて出す |
| 見積り | 子どもから「これを○ptでやりたい」と逆提案できる。親が承認すると仕事になる |
| 受注・完了・承認 | 子どもが受注 → 完了報告 → 親が確認して報酬を付与。納得できなければ差し戻せる |
| 定期発注 | 毎週◯曜日、毎月◯日の仕事を0:00に自動追加。受注操作は不要で、いきなり進行中になる |
| 定期一覧 | 自動発注される仕事の一覧。あとから内容・曜日・時刻を編集できる |

### お金の使い道

| 機能 | 説明 |
| --- | --- |
| 家庭内銀行 | 預けると月0.1%の利息がつく。貯める動機をつくる |
| 資産運用 | 日本株・米国株に見立てた値動きに投資できる。1日／1週間／1か月で推移を確認できる |
| チケット | 「ゲーム1時間」などを親が登録し、子どもがポイントで購入する |
| 換金申請 | ポイントを現金に換えたいと子どもが申請し、親が承認する |
| 自動支払い | スマホ代などを定期的に引き落とす。残高不足ならマイナスになり、株の購入と換金がロックされる |
| ギフト | 親からメッセージ付きでボーナスポイントを贈る |

### 続けるための仕組み

- 残高が変わると数字がスロットのように回るアニメーション
- お手伝いスタンプカードと連続達成日数
- **プッシュ通知**：アプリを閉じていても、新しい仕事・見積り・完了報告・ギフト・換金申請・期限1時間前が通知センターに届く
- フリガナ（ルビ）表示の切り替え
- **使い方ガイド**：設定から起動すると、ホーム画面の機能を1つずつスポットライトで案内する

## プッシュ通知の仕組みと設定

### なぜサーバーが必要か

ブラウザの `new Notification()` は、ページが開いている間しか動きません。アプリを閉じるとJavaScriptが止まるので、通知を作る人がいなくなります。

そこで **Firebase Cloud Messaging（FCM）** を使い、Firestore の変化を **Cloud Functions** が見張って、サーバー側から通知を送るようにしました。受け取り役はブラウザが裏で動かすサービスワーカー（`sw.js`）なので、スマホがスリープ中でも通知センターに届きます。

受け取り役は、オフライン対応をしている `sw.js` にまとめてあります。以前は通知専用のサービスワーカーを別スコープに登録していましたが、その方式ではアプリを完全に終了させたときに通知が届きませんでした。画面を受け持っているサービスワーカー自身に受け取らせることで確実になります。

端末は `pushTokens` コレクションに自分の宛先（トークン・同期ID・役割）を登録します。Cloud Functions は「この家族の子供の端末ぜんぶ」を検索して送ります。無効になった宛先は自動で削除されます。

### 設定手順

**1. 匿名ログインを有効にする**

Firebaseコンソール → Authentication → Sign-in method → 「匿名」を有効化。

**2. ウェブプッシュ証明書を作り、鍵を貼る**

Firebaseコンソール → プロジェクトの設定 → Cloud Messaging → 「ウェブプッシュ証明書」→ 鍵ペアを生成。

表示された文字列を `push.js` の `VAPID_KEY` に貼ります。

```js
const VAPID_KEY = 'BB....(生成された鍵)';
```

**3. Cloud Functions をデプロイする**

Node.js（20以上）と Firebase CLI が必要です。

```bash
npm install -g firebase-tools
firebase login

cd functions
npm install
cd ..

firebase deploy --only functions
```

**4. セキュリティルールをデプロイする**

```bash
firebase deploy --only firestore:rules
```

**5. アプリ側で通知をオンにする**

アプリの設定画面にある「通知を受け取る」をタップします。**iPhone / iPad では、Safari の共有ボタンから「ホーム画面に追加」して、そのアイコンから開いた場合のみ通知が使えます**（iOS 16.4 以降）。ブラウザのタブから開いている状態では許可が取れません。

### 動作確認

Cloud Functions のログで送信結果が見られます。

```bash
firebase functions:log
```

`[notify] 成功1 / 失敗0` のように出れば届いています。`[notify] 宛先なし` の場合は、その端末で「通知を受け取る」をまだ押していません。

### 設定が済んでいないときの動き

VAPIDキーが未設定、または通知が許可されていない場合は、これまでどおり**アプリを開いている間だけの通知**に自動で切り替わります（`app.js` の `localNotify`）。サーバー通知が有効になったときは、同じ内容が2回出ないよう端末側の通知は止まります。

## 使いはじめかた

### 1. 親の端末

1. アプリを開き「親として開始」を選ぶ
2. メールアドレスを入力し、届いたリンクから戻る
3. パスワードとお子さまの名前を設定すると **同期ID**（6文字）が発行される

### 2. 子どもの端末

1. アプリを開き「子供として開始」を選ぶ
2. 親の画面右上に出ている同期IDを入力する

これで親子の画面がつながります。

### 3. 兄弟姉妹を増やす・減らす

お子さまは設定画面の「お子さまを追加」から登録します。同期IDはお子さまごとに発行されます。ふたり以上になると親のホーム画面の上に名前が並び、タップでその子の口座に切り替わります。まだ端末がつながっていない子には砂時計が付きます。

削除は設定画面のお子さま一覧のゴミ箱から行います。お仕事・ポイント・株・チケット・履歴もまとめて消え、元には戻せないため、確認のあとに名前を入力してもらう作りにしました。

ひとりだけのときは削除できません。口座がなくなると同期IDを持たない状態になり、親は新しいお子さまを登録する入口（設定画面）にも入れなくなってしまうためです。

削除の順番には決まりがあります。`tasks` などのデータを消してから、最後に `families` の書類を消します。セキュリティルールが「その家族のメンバーかどうか」を `families` を見て判断しているので、先に家族を消すと残ったデータを消す権限を失ってしまいます。通知の宛先（`pushTokens`）は一覧で引けない決まりにしてあるため端末からは消せず、`onFamilyDeleted` という Cloud Functions が受け持ちます。

## 技術構成

| 種類 | 使用技術 |
| --- | --- |
| フロントエンド | Vanilla JavaScript（ES Modules）。ビルド不要 |
| スタイル | Tailwind CSS（CDN）＋ 自前の `style.css` |
| グラフ | Chart.js |
| 認証 | Firebase Authentication（親はメール＋パスワード、子どもは匿名認証） |
| データベース | Cloud Firestore |
| 通知 | Firebase Cloud Messaging ＋ Cloud Functions（アプリを閉じていても届く） |
| オフライン対応 | Service Worker（PWA） |

フレームワークもビルドツールも使わず、ブラウザがそのまま解釈できるコードだけで作っています。ファイルを置けば動くため、仕組みを最初から最後まで自分で追いかけられることを重視しました。

### ファイル構成

```
index.html                画面の土台と読み込み
app.js                    アプリの中心。Firebase との通信、各操作の処理
ui.js                     画面の描画。state を見てHTMLを組み立てる
state.js                  アプリ全体の状態をまとめて持つ
utils.js                  アイコン、ルビ、株価計算などの部品
dialog.js                 alert/confirm/prompt の代わりになるダイアログ
tutorial.js               使い方ガイド（スポットライト案内）
push.js                   プッシュ通知の受け取り準備
firebase.js               Firebase の初期化
style.css                 見た目の調整
sw.js                     Service Worker（オフライン対応＋通知の受け取り）
manifest.json             PWA の設定
firestore.rules           Firestore のセキュリティルール
functions/index.js        通知を送るサーバー処理（Cloud Functions）
```

## セキュリティの考え方

家族のお金のデータを扱うため、次の3点を設計の柱にしています。

**1. 自分の家族のデータしか触れない**

`firestore.rules` で、`families/{同期ID}` の `parentUid`（親）または `childUids`（子どもの端末）に含まれる人だけが、その同期IDにひもづくデータを読み書きできるようにしています。ルールを書いていないコレクションはすべて拒否されます。

**2. 子どもの端末も匿名認証でログインする**

同期IDを入力しただけの未ログイン状態では、Firestore 側で本人確認ができません。そこで子どもの端末は匿名アカウントでログインし、その uid を家族の `childUids` に登録します。これにより「同期IDを知っているだけの第三者」を締め出せます。

**3. 入力された文字をそのまま画面に出さない**

仕事名やギフトのメッセージは家族が自由に入力できます。これらは `utils.js` の `esc()` を通してから画面に出しており、`<script>` のような文字列を書かれても、ただの文字として表示されます。

さらに、お金が動く処理（報酬の付与、チケット購入、換金承認、ギフト受け取り）は Firestore の **トランザクション** で行っています。二重タップや通信のやり直しで、ポイントが二重に増えたり、承認だけ通ってポイントが増えないといった食い違いが起きないようにするためです。

### ルールの反映

`firestore.rules` は**デプロイして初めて有効**になります。

```bash
npm install -g firebase-tools
firebase login
firebase deploy --only firestore:rules
```

Firebase コンソールの Authentication で **「匿名」** のログイン方法を有効にしておいてください。子どもの端末が接続できなくなります。

## ローカルでの動かしかた

ES Modules を使っているため、ファイルを直接ダブルクリックしても動きません。簡易サーバー経由で開いてください。

```bash
# Python がある場合
python -m http.server 8000

# Node.js がある場合
npx serve .
```

ブラウザで `http://localhost:8000` を開きます。

### 開発中の注意

各ファイルの読み込みには `?v=136` のようなバージョン番号を付けています。**JavaScript や CSS を編集したら、この番号をすべてのファイルで揃えて上げてください。** 番号がずれると、古いキャッシュが残ったり、同じファイルが二重に読み込まれて状態が共有されなくなります。

対象は `index.html`、`app.js`、`ui.js`、`utils.js`、`dialog.js`、`tutorial.js`、`push.js` の冒頭にある import 文と、`sw.js` の `VERSION` です。`firebase.js` の import にも番号が必要です（ここを忘れると `firebaseApp` が見つからないというエラーになります）。

## 公開のしかた（GitHub Pages）

`main` ブランチに push すると `.github/workflows/pages.yml` が動き、ファイルがそのまま公開されます。

```bash
git add -A
git commit -m "変更内容のメモ"
git push
```

リポジトリの Settings → Pages で、Source が **GitHub Actions** になっている必要があります。「Deploy from a branch」にすると GitHub が Jekyll を通してから公開しようとしますが、このアプリは静的ファイルを置くだけなので Jekyll は不要で、そのビルドが失敗すると公開が止まりサイトが 404 になります。

Source を切り替えた直後は公開がいったん取り消されるため、もう一度 push するか Actions から再実行して公開し直してください。

## 開発の記録

このアプリは、家庭でのお小遣いのやりとりに感じた違和感から作りはじめました。決まった額をもらうだけでは、お金が何と引き換えに手に入るのかが見えません。そこで「仕事を受けて、報酬を得て、貯めるか使うか運用するかを自分で決める」という流れをそのままアプリにしました。

作りながら特に考えたのは次の点です。

- **子どもからも提案できるようにする。** 親が出す仕事だけだと、結局は指示されたことをこなすだけになります。見積り機能を入れて、子どもが自分で仕事を作れるようにしました。
- **マイナス残高を許す。** 支払いで残高が足りないとマイナスになります。そのあいだは株も換金も止まります。使いすぎると困る、という感覚を安全に体験できます。
- **失敗しても壊れないようにする。** 電波の悪い場所で二重にタップされてもポイントがずれないよう、お金が動く処理はすべてトランザクションにしました。
